## Engineering Standards

| Standard | Operating rule |
|---|---|
| **CI/CD** | GitHub Actions validates profile contracts and generates telemetry; application pipelines should separate build, test, smoke-test, deployment, and rollback stages. |
| **Test discipline** | Pytest and Node-based safety checks are verified in the current worker. Jest is used for JavaScript units and Playwright for browser flows when a project actually contains those layers. |
| **TDD** | Acceptance criteria become executable tests before implementation whenever behavior can be isolated and reproduced. |
| **Versioning** | Public releases follow Semantic Versioning only after a stable external contract exists; unreleased experiments are never dressed up as production versions. |
| **Security** | Secrets stay out of source, logs, badges, telemetry, and public architecture diagrams. Authentication fails closed. |
| **Observability** | Runtime claims require timestamps, structured evidence, and a reproducible health signal—not screenshots alone. |
| **Pull requests** | Small diff, explicit scope, linked issue, actual test output, risk notes, and rollback guidance when the change can affect production. |

## How I Execute Paid or Open-Source Work

1. Verify the issue is open, eligible, and genuinely uncompleted.
2. Read contribution rules, tests, linked pull requests, ownership, and acceptance criteria.
3. Reproduce the problem before proposing implementation.
4. Confirm scope only when the repository requires assignment or clarification.
5. Build the smallest correct change on an isolated branch.
6. Run real tests and publish actual output—never fabricated coverage or performance.
7. Submit a focused pull request with tradeoffs, evidence, and review notes.
8. Respond to maintainer feedback without expanding scope silently.
