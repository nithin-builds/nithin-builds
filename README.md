## How I approach an issue

1. Confirm that the issue is open, genuinely uncompleted, and still eligible.
2. Read the repository rules, contribution guide, tests, and acceptance criteria.
3. Check linked pull requests and maintainer activity to avoid duplicate work.
4. Share a short implementation plan only when the repository expects discussion.
5. Build the smallest correct change on a separate branch.
6. Run relevant tests and report actual results—never fabricated evidence.
7. Submit a focused pull request with reproduction steps, tradeoffs, and screenshots when useful.
8. Respond professionally to review feedback.

## Good project fit

I am most useful when a task has:

- A reproducible bug or clearly defined feature
- Written acceptance criteria
- A public repository and review process
- A stated budget or bounty amount
- A reachable maintainer and reasonable deadline

I do **not** begin paid work from vague promises, closed/solved issues, payment-request threads, or listings with unclear ownership.
